# 广告追踪引导 / 广告权限弹窗 / 广告关联开关 —— 实现与埋点说明

> 需求：《广告跟踪引导 & 广告权限弹窗的出现时机》《广告追踪激励策略》
> 代码位置：`Assets/FourWordIdiom/LocalGame/GameScripts/Controller/AdTrackingManager.cs`（流程编排）
> `Assets/FourWordIdiom/LocalGame/GameScripts/RootContainer/Launch/AdTrackingGuidance.cs`（引导页 UI）

## 一、流程

| 场景 | 触发条件 | 行为 |
| --- | --- | --- |
| 首次加载 | 隐私已同意 + 系统授权状态 = 未决定 + 未弹过引导 | **加载页显示的同时（约 0.05s）**在加载页之上盖引导页（"请允许关联" / "关联应用" / 说明文案 + "继续"）；不等登录、不等分层配置，"+G" 奖励标签拿到配置后再补 |
| 点"继续"（第一次） | 引导页按钮 | 拉起系统广告追踪弹窗（iOS ATT / 鸿蒙 APP_TRACKING_CONSENT），弹窗盖在引导页上层；期间按钮置灰 |
| 授权结果返回 | 系统弹窗回调 | 引导页保持不动，按钮恢复可点 |
| 点"继续"（第二次） | 引导页按钮 | 关闭引导页 → 加载流程继续 → 进游戏 |
| 设置里"广告关联" | 玩家**拒绝**过授权 + 分层配置 `AdTrackingStimulate` 的 S=1 | 设置界面多一行"广告关联"开关，点它再出引导页，按钮文案 = "去开启" |
| 点"去开启" | 引导页按钮 | 跳系统设置（iOS：本 App 设置页）→ 回前台校验，仍拒绝则提示"尚未开启广告关联" |

### 关键约束（"不要不经过加载页直接进游戏"）

`LoadingController.LoadingSequence()` 在 `allowSceneActivation = true` 之前会 `yield return AdTrackingManager.WaitStartupFlowFinished()`，
只有引导页关闭后才切场景；之后还有 0.35s 停留，保证玩家看到加载页走完（版号 / 防沉迷提示在这一屏）。
即：加载本身在引导页背后照常跑完，但**不会跳过加载页**直接进大厅。

## 二、激励（AdTrackingStimulate = S_G）

- 数据源：`shop_layer.csv` 的 `AdTrackingStimulate` 列，按用户分层取值（如 `IAA01 = 1_200`、`IAA02 = 1_500`，其余 `0_0`）。
- 读取入口：`ShopManager.TryGetAdTrackingStimulate(out bool enabled, out int gold)`。
- S=1 且 G>0 时：
  - 设置开关文字下方显示 `+G`（金色）；
  - 引导页按钮上方显示 `+G金币`；
  - 玩家同意授权后发放 G 金币，`UserData.adTrackingRewardClaimed = true`，**只发一次**；
  - 弹窗表现复用 `AdsAwardScreen`（领取金币奖励弹窗）：在大厅内立刻弹；首启在加载阶段授权的，进大厅后由 `GameCoreManager.Start` 补弹。

## 三、埋点现状与方案（通用数数 ThinkingData）

### 3.1 结论

| 项 | 之前 | 现在 |
| --- | --- | --- |
| 广告追踪 | 只有鸿蒙：`PushMessageReceiver.OnOAIDClosedSignal` 里上报 `Pop_up` + `Pop_accept/refuse`，且仅在 `adTrackingEnabled` 为空时写一次；iOS/安卓无 | 统一到 `AdTrackingManager`，引导页 + 系统弹窗 + 结果 + 奖励四个点全覆盖 |
| 消息推送 | `Push_harmony` 内已上报 `Pop_up` / `Pop_accept` / `Pop_refuse`，但 `PushMessageReceiver.OnSettingsClosedSignal` 又重复上报一次 → 一次授权产生 2 个 `pop_up` | 删掉重复上报，只保留 `Push_harmony` 的一处 |

### 3.2 事件表（广告追踪）

| 事件 | 触发时机 | 属性 |
| --- | --- | --- |
| `Pop_up` | 引导页展示（首发 / 设置入口各一次） | `pop_name = 广告追踪引导` / `广告追踪引导-设置` |
| `Pop_up` | 拉起系统权限弹窗（原生弹窗时机拿不到，用发起时刻兜底） | `pop_name = 广告追踪` |
| `Pop_accept` | 系统弹窗点"允许"，或从系统设置里手动开启 | `pop_name = 广告追踪` |
| `Pop_refuse` | 系统弹窗点"不允许" | `pop_name = 广告追踪` |
| `resource_change` | 发放激励金币 | `resource_id = 0`、`change_type = 获得`、`change_num = G`、`change_reason = 广告追踪激励` |

> `change_reason` 的匹配顺序已调整：`广告追踪` 必须在通用 `广告` 之前，否则会被收敛成"金币广告弹窗获得"。
> 说明：`广告追踪激励` 目前不在《通用数数埋点方案》的 change_reason 枚举里，先按原值上报，待规范回填后同步。

### 3.3 事件表（消息推送，已存在）

| 事件 | 触发时机 | 属性 |
| --- | --- | --- |
| `Pop_up` | `Push_harmony.RequestEnableNotification()` 首次请求 | `pop_name = 消息推送` |
| `Pop_accept` / `Pop_refuse` | `Push_harmony.HandleSettingsClosedFromJS()`（玩家从系统通知设置返回） | `pop_name = 消息推送` |

### 3.4 建议补充（未实现，需产品/数数确认口径）

1. `广告关联开关点击`：如果希望单独看"设置入口"的转化，可在开关点击时补 `ui_open` 或独立 pop_name（当前用 `广告追踪引导-设置` 的 `Pop_up` 已能区分）。
2. `广告追踪授权状态` 作为用户属性（`user_set`）：`ad_tracking = 1/0`，便于按授权状态做人群/留存分析。
3. iOS 首启若广告 SDK 抢先弹了 ATT（Pangle 若开启自动请求），引导页会因"系统已有结果"而不再出现，需确认 SDK 侧关闭自动请求。

## 四、平台差异 / 已知取舍

1. **iOS**：新增 `Assets/Plugins/iOS/AdTrackingBridge.mm`（ATT 状态查询 / 请求 / 跳设置），
   出包脚本 `Assets/Editor/BuildEditor/AdTrackingPostProcessBuild.cs` 自动写入 `NSUserTrackingUsageDescription` 并弱链接
   `AppTrackingTransparency` / `AdSupport`。
2. **鸿蒙**：`Game.LoadAds_OAID()` 内部就是 `LoadBanner → SendOAID.RequestOAID()`，授权框和 Banner 加载绑在一起，
   所以现在只在"引导页点继续"时才调用；拒绝授权的玩家不再每次启动重复请求（避免反复弹框），代价是这类玩家的 Banner 可能拿不到 OAID。
   若要彻底解耦，需要 ArkTS 侧单独暴露一个"仅请求跟踪授权"的方法。
3. **安卓**：GAID/广告 ID 没有运行时授权概念，`PlatformSupportsTracking = false`，整套流程不触发。
4. **编辑器**：走本地模拟（`PlayerPrefs.att_mock_status`），`att_mock_deny = 1` 可模拟拒绝；清掉 key 可重走首发引导。

## 五、怎么验证弹窗时机

1. 正常跑一遍：Console 里会有 `[AdTracking] 加载页已显示，准备弹出广告追踪引导页`，紧随其后（约 0.05s）引导页就盖在加载页上。
2. 没看到弹窗时，Console 会打印**具体原因**：`[AdTracking] 本次加载页不弹广告追踪引导：xxx`
   （常见：`引导页已经弹过` / `系统里已有授权结果（Authorized）` / `隐私协议还没同意`）。
3. 反复验证：编辑器执行 `AdTrackingManager.ResetGuideStateForDebug()`，或 `PlayerPrefs.SetInt("att_mock_always_show", 1)` 让每次进加载页都弹。
